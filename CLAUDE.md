# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

An IBM PC/XT core for the Karabas Go, Mini and Mini G boards (Spartan-6 XC6SLX25-2 FTG256, ISE 14.7): MCL86 (8088), KFPC-XT (the chipset), Graphics Gremlin (CGA), JTOPL (Adlib), an SN76489 (Tandy sound). It started as the PCXT_Xilinx_Spartan_6 port by spark2k06 (many boards: ZXUno, ZXDos, NGo, UnoXT, ZXDos+); those boards and their `ifdef`s were removed in Ф3 (2026-10-31). GPL v3 (LICENSE.txt). The MCU link, OSD, disk images, HDMI and DACs come from `karabas-go-modules` (submodule `modules/`, its `master`). The plan of the work (modules, bugs, MiSTer fixes and features, HDD and floppy images) is `docs/PLAN.md`; the inventory of PCXT_MiSTer commits (ported, to port, not needed) is `docs/UPSTREAM.md`.

## Layout

- `src/`: the build: `Makefile`, the tops `karabas_go_top.v` / `karabas_mini_top.v` / `karabas_minig_top.v` (pins, clocks, VGA / HDMI, DAC, MIDI clock), their `.ucf`, the build inputs `.prj` / `.xst` / `.ut` (the local `.gitignore` un-hides them), `config.vh` (the feature switches, shared by the three tops), `core*.json`, `rom/` (the BIOS images of the json), the results `karabas_<board>_top.bin` / `pcxt.kg*`, `sim/`, `rtl/`.
- `src/rtl/`: `karabas_pcxt.v` (the machine the tops share: `system`, `kg_mcu`, the soft switches, the serial mouse, the OSD overlay; the audio registered in clk_50, `osd_command` taken into clk_vga by a toggle handshake), `system.v` (the PC), `pcxt_disks.v` + `pcxt_fdd.v` (disks, see MCU link), `midi_clk.v`, `hdmi/` (`hdmi_frame.v` fits the sync into 720x480; `zhdmi_top.v` + `hdmi_pll.v`, copies of next186's at 28.571 MHz), `mouse/` (`hid_parser.vhd` + `serial_mouse_convertor.vhd`: the USB mouse as a serial mouse), `cpu/` (MCL86 2026), `chipset/` (KFPC-XT: `Chipset.v`, `Peripherals.v`, `Bus_Arbiter.v`, `Ready.v`, `XT2IDE.v`, a dir per KF block), `video/` (CGA, scandoubler, UM6845R), `uart/` (16750 of the mouse, `mpu401_tx.v`), `sound/jtopl`, `sound/sn76489`, `common/` (`ram.v`, `bram.v`, `dcm.v`, `clk_div3.v`, `floppy.v`, `simple_fifo.v`, the `.hex` files of the BIOS / XTIDE / splash). `$readmem` files are found next to the source that reads them. Check the `.prj` file list before assuming a file is built.
- `modules/`: the submodule `karabas-go-modules` (relative URL `../karabas-go-modules.git`), in the `.prj` files as `../modules/rtl/...`. Clone with `--recursive` or run `git submodule update --init`.
- `SW/`: `8088_bios` (Turbo XT BIOS source), `ROMs` (BIOS images, `make_rom_with_*.py`), `splash/karabas_go`. `hdd/`: DOS tools for the disk image (CTMOUSE, DOSMAX, LTEMM, GET_RTC). `docs/`: PLAN, UPSTREAM, `img/`.

## Build

- `src/Makefile` (ISE 14.7 command line, sources `/opt/Xilinx/14.7/ISE_DS/settings64.sh`): `make go|mini|minig`, steps `<board>-xst`, `-impl`, `-core`, `make <board>-report`. Inputs per board: `karabas_<board>_top.prj` (the source list, paths relative to `src/`; add new files here), `.xst`, `.ut`, `karabas_<board>.ucf`. Map cost table `MAP_T_<board>` = 2. ISE writes its other outputs into `src/` (ignored). A Mini G build takes about 4 min (XST 2, map 1, PAR 1).
- `config.vh`: `ROM_BIOS` `xtsergey.hex`, `XTIDE_BIOS` `xtide.hex`, the splash, and the switches `SOUND_ADLIB`, `SOUND_TANDY`, `MOUSE_COM1`, `FLOPPY` (with `FDD_CLOCK_RATE`, the chipset clock), `RTC_MCU`, `MIDI_MPU401`. The board options of the upstream port (`KARABASGO`, `EMULATE_PS2`, `PHYSICAL_IDE`, `AUDIO_DAC`, `VIRTUAL_BUTTONS`, `BIOS_16KB`, `ROM_LOADER` on; `MEM_512KB`, `PHISICAL_BUTTONS`, `BIOS_WRITABLE` off) are resolved in the code.
- Clocks: `rtl/common/dcm.v` makes 100, 50 (`clk_chipset`, the MCU link) and 28.571 MHz (`clk_vga`) from `CLK_50MHZ`. `system.v` divides `clk_vga` to the CPU clock (14.29 MHz, the comments say 14.318) and 4.77 MHz for the peripherals.
- CPU: `rtl/cpu` is sv2v of MiSTer PCXT `3238779` `rtl/8088` (the MCL86 of Boogermann / opengateware: EU, BIU max, adder, `mcl86_ucode.v` + `mcl86_ucode.mem`; MIT headers kept). `system.v` ties `cycle_accrate` = ~turbo, `shift_read_timing` = turbo, counter ratio 0 / decrement 1, 8088 (`is8086` 0, `fake286_flags` 0, no word path). XST merges the second microcode ROM copy (`mem_sel`) into the first. Verified on Mini G 26103109 (DOS, games, turbo, hot reset). The old MCL86 of 2022 (microcode `6db8e53`, the OF / INTR fixes, local `// karabas:` timing edits) was removed after that; it is in git history (`fcc2d66`, `HW/8088`).
- Timing (build 26103109, Mini G): all constraints met, 66 % LUTs, 90 % slices, 31 RAMB16. The ucf derives the clocks from `CLK_50MHZ` (`dcm_system` 100 / 50 / 28.571 MHz of one PLL); TIG between 28.571 and 100 / 50 MHz (the upstream design crosses them freely); `TS_AUDIO_PIX` TIG from clk_50 into the HDMI pixel clock (zhdmi_top filters the samples); `TS_CPU_ADDR` 20 ns from `cpu_address` (latched at ALE, held for the bus cycle) to clk_50.
- Packing: `src/make_core.py` is a symlink to `../../karabas-go-tools/make_core/make_core.py`, so the tools repo must sit next to this one. `make <board>-core` runs it (`core.json` -> `pcxt.kg1`, `core_mini.json` -> `pcxt.kg2`, `core_minig.json` -> `pcxt.kg3`). Set `"build"` (YYMMDDHH) in the json first. The `.bin` and `.kg*` files are committed.

## MCU link

- `type: "osd"` (Menu+Esc opens the OSD; `main` had `none`, which the firmware calls `CORE_TYPE_HIDDEN`: listed in the browser but no OSD). `spi_freq` 32 on Mini G (bursts at 32 MHz), the default 16 MHz on Go / Mini; `eeprom_bank: 255`, `roms`: the BIOS and the XTIDE BIOS (see BIOS).
- BIOS: the BIOS (16 KB block RAM at FC000-FFFFF) and the XTIDE BIOS (EC000-EFFFF) start with the `.hex` files (`xtsergey.hex`, `xtide.hex`) and are written again by the rom loader of `kg_mcu` from the `roms` of `core*.json` (`rom/bios_sergey_xt.rom` at 0, `rom/xtide.rom` at 4000h; an 8 KB BIOS such as `rom/bios_turbo_xt31.rom` goes to 2000h, so it lands at FE000). The PC stays in reset while `ROMLOADER_ACTIVE`. A different BIOS needs only `make <board>-core` (or `"external": true` in the json: the firmware reads the file from the SD card). Sergey Kiselev's XT BIOS 1.0.0a (the `pcxt_xtsergey.rom` build of MiSTer, `MACHINE_XT`, two 1.44M drives without CMOS) replaced the Turbo XT BIOS 3.1 (`pcxt31.hex`, the same bytes as MiSTer's `pcxt_pcxt31.rom`), which knows only 360K drives: DOS 6.22 did not start from a 1.44M image with it. `kg_mcu` has `ENABLE_FILE` 0.
- `kg_mcu` answers `CMD_CAPS` with `BURST_MAX_MHZ`: 32 on Mini G (MCU_SCK on a global clock pin), 0 on Go / Mini (bursts at the link clock). Burst lines: Mini / Mini G `MCU_IO[0]` cs_n (PULLUP) / `MCU_IO[1]` ready; Go `MCU_SPI_IO[1]` cs_n (M11, PULLUP) / `MCU_SPI_IO[0]` ready (N9). File mounter: `ENABLE_IMG` 1, `img_sdc` + `hdf_ata` in `pcxt_disks`.
- OSD: `kg_osd_overlay` in clk_vga over the 18-bit RGB of `system`, H_OFFSET 48 / V_OFFSET 18 (tuned on Mini G).
- Soft switches (`kg_soft_switches` N=8, register n = item n of `core*.json`, the file items count): 0 Video mode (RGB / VGA, Menu+F11) and 1 Turbo (Menu+F12) drive `btn_green_n_i` / `btn_yellow_n_i` of `system` as levels (scandoubler and turbo follow the switch). 2 HDD0 (CF card / Image, default Image), 3 HDD0 image and 4 HDD1 image (file slots 0 / 1, Menu+F1 / F2, no value), 5 FDD A image and 6 FDD B image (file slots 2 / 3, Menu+F3 / F4, no value), 7 Reset (hotkey Ctrl+Alt+Del, a trigger: the firmware sends a pulse) resets the whole PC through `reset_in` of `system` (`kb_reset | areset`), as at the end of the splash screen. Ctrl+Alt+Del also reaches the BIOS as keys.
- Keyboard: the MCU sends XT scancodes with `CMD_PS2_SCANCODE` (0x0B, address 0x01). `kg_mcu` puts them on `XT_SCANCODE` (toggle `XT_SCANCODE_UPD`) into `system` (`kb_scancode`). Address 0x00 (the PS/2 sequence) is ignored.
- Mouse: `hid_parser` turns the USB mouse moves of `mcu` into a serial mouse on COM1 (`serial_mouse_convertor`, `MOUSE_TX` / `MOUSE_RTS`).
- Disks (`rtl/pcxt_disks.v`): the XTIDE BIOS (ports 300h) goes through `XT2IDE` (8 to 16 bit; the IDE data bus of `system` / `Chipset` / `Peripherals` is split into `ide_dout` / `ide_din`, no tristate inside the FPGA) to the CF card on the `W*` pins and to `hdf_ata` with `img_sdc` (slots 0 / 1 of the file mounter, `.img .vhd .hdf .bin .raw`). HDD0 = CF card: the card is device 0 and the HDD1 image device 1 (data from the card while DEV = 0); HDD0 = Image: the card gets no chip select, the images are devices 0 and 1. The chip select of XT2IDE ends with the strobe (`iorq` is `io_read_n | io_write_n`), but `hdf_ata` acts at the end of the strobe: `pcxt_disks` latches cs / address / data during the strobe and delays the strobes by a clock. `hdf_ata` resets with the PC. Known: `hdf_ata` sets BSY while it examines a new image, so a command must wait for BSY after selecting the device (the BIOS does). The SD pins of the FPGA are tied off.
- Floppies (`FLOPPY`): `rtl/common/floppy.v` (the controller of MiSTer PCXT, from ao486, BSD; as Verilog-2001, its fifo `simple_fifo.v` 512 deep) in `Peripherals.v` with the glue of MiSTer's `Peripherals.sv`: ports 3F0-3F5 / 3F7, IRQ 6, DMA channel 2 (`fdd_dma_req` into `dma_request[2]` of the 8237 in `Chipset.v`, DACK 2, TC; `terminal_count_n` of `Bus_Arbiter` is active high despite its name). The KF8237 of the upstream fork (2022-10) lost the TC: `Ready.v` gives DMA cycles with IOR / IOW a wait state and `dma_ready` back as a short pulse, and the old `KF8237_Timing_And_Control` cleared TC in the wait states (the read never ended, on hardware endless sector reads). The KF8237 files are now sv2v of MiSTer `baaac36` (fixes `fc23647`, `49b97f9`, `baaac36`); `sim/run_dma_sim.sh` (`tb_dma_fdd.v`: a read, `tb_dma_fdd_wr.v`: a write with the memory as `ram.v` + `data_bus_out` deliver it; KF8237 + `Ready.v` + a copy of the glue + `floppy.v`, no `Bus_Arbiter` / KF8288) fails with the old KF8237. KF8237 does not mask a channel after its TC (a real 8237 does); the floppy drops DREQ itself. KF8288 had DEN active while the DMA had the bus (the CPU waits inside its next cycle; in a write cycle `Bus_Arbiter` put the CPU data on the internal bus): floppy writes stored bytes of the CPU stack (far pointers F000:xxxx, 0040) in the sectors. Fixed as MiSTer `4f8cd84` (`data_enable` gated by `command_enable`). The RAM of `Peripherals.v` needed `~address_enable_n`, so no DMA reached it: under `FLOPPY` the memory cycles of DACK 2 select it too. DIP switches: two drives always (`sw` `01101101`), so B can be mounted at any time. The management bus of `floppy.v` (MiSTer: the HPS) goes up through `Chipset` / `system` to `pcxt_fdd` in `pcxt_disks`: geometry from the image size on mount (160K to 2.88M), the sector reads into the fifo, the writes / formats out of it through a sector buffer, slots 2 / 3 of `img_sdc` (after the HDD slots: the lowest slot first).
- Simulation: `src/sim/run_disks_sim.sh` (iverilog): `tb_disks.v`, the XT bus as the XTIDE BIOS drives it + `XT2IDE` + `pcxt_disks` + a model of the mcu (from next186 `tb_ata.v`): IDENTIFY, LBA and CHS reads, after a reset, device 1 in CF mode; ends with `tb_disks: 0 errors`. Without the strobe latch it fails. `sim/run_fdd_sim.sh`: `tb_fdd.v`, `floppy.v` on its own io / DMA pulses (as the glue makes them) + `pcxt_disks` (`pcxt_fdd`) + the mcu model with writes: geometry, a two-sector read, a write and its read back, drive B, a format of a track (all 9 sectors: fails without `cmd_format_input_cut`), unmount; ends with `tb_fdd: 0 errors`. `+trace` prints the states, `+vcd` dumps. `sim/run_cpu_sim.sh`: `tb_cpu_flags.v`, the i8088 of `rtl/cpu` alone , runs the program of `gen_cpu_flags.py` (384 ADD / ADC / SUB / SBB cases) and checks the pushed flags; ends with `tb_cpu_flags: 0 errors` (about 1 to 2.5 min). `sim/tb_mpu401.v` (MIDI, run by hand with iverilog).
- RTC (`RTC_MCU`): ports 2C0h (index) / 2C1h (data) of `Peripherals.v` go up through `Chipset` / `system` to `kg_mcu_rtc` (`ENABLE_RTC` 1): MC146818 registers the firmware keeps (time every 500 ms; with `eeprom_bank` 255 the firmware since #97 sends A 26h / B 02h, 24 h, BCD; older firmware sent B FFh with BCD time). As MiSTer: the BIOS does not read it, `GET_RTC.EXE` (`hdd/`) sets the DOS time.
- MIDI (`MIDI_MPU401`): `rtl/uart/mpu401_tx.v`, an MPU-401 in UART mode at 330h / 331h, output only (31250 baud, one byte buffered, no IRQ, acknowledge FEh), to `MIDI_TX` of the board synthesizer; Go (test points L12 / M12 / L10) and Mini also get `MIDI_CLK` 12 MHz (`rtl/midi_clk.v`, a DCM on clk_50), `MIDI_RESET_N` high.
- Memory: the 8-bit SRAM (`MA`, `MD[7:0]`, `MWR_N[0]`). The SDRAM, flash, FT812 SPI pins are tied off.
- Video: Go has VGA (6 bits per color padded to 8, `V_CLK`). Mini and Mini G: HDMI (`hdmi_frame`, then `zhdmi_top`, audio on unless `DVI_ONLY`, which crosses into clk_vga through `kg_sync`).
- Audio: `AUD_L` / `AUD_R` of `system` (16 bit, two's complement) to `kg_pcm5102` (Go, Mini G; `DIV_BITS` 2 as before) or `kg_sigma_delta_dac` (Mini, `AUDIO_L` / `AUDIO_R`, a quarter of full scale as before) and HDMI. The ADC pins are tied to 0.
- `FT_CLK_OUT` = clk_50 / 6 = 8.33 MHz on Mini and Mini G (an unclocked FT812 hums into the audio; the rule for all cores).
